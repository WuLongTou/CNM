# 斩妖录（Web 版）

简笔画速写本风除妖生存 roguelike：扮演除妖师，在持续逼近的妖潮中存活。
TypeScript + PixiJS v8 实现的完整重写版。玩法数值对齐 C# 旧版数据表，
**主题为「斩妖」设定**：玩家是除妖师，敌人统称妖物。仓库内不含任何旧引擎工程文件。
美术为**简笔画（速写本）风格**：米白纸面世界 + 炭棕手绘线条 + 血红点缀，
全部角色贴图由 `tools/gen-sketch.mjs` 程序化生成（seed 固定可复现）。

## 架构

```
src/
  sim/      纯逻辑层（零 DOM/渲染依赖）：状态机、开局职业、除妖师、妖物 AI、武器、伤害、
            刷怪、难度、天气、成就、结算。固定 60Hz 步长 + 种子化 PRNG → 同 seed 同输入
            同结果，vitest 直接跑。
  render/   PixiJS v8 渲染层：只读 sim 状态绘制（地面/实体/弹道/相机/帧动画）。
  ui/       DOM UI 层：HUD、欢迎、暂停、帮助、装备、合成、结算、触屏控件等（手账血色风）。
  app/      装配：主循环（固定步长累加器）、键盘+触屏输入合成、debug API、音频。
            数值表直接内聚于 sim/（config.ts 妖物三维与天气、weapons.ts 武器表、
            recipes.ts 配方，源自 C# 版数据）。
tests/
  sim/      vitest 逻辑回归。
  e2e/      Playwright E2E（完整对局闭环）。
tools/      资产管线：gen-sketch.mjs 程序化生成简笔画源图（玩家/妖物/地面），
            sync-assets.mjs 从 assets-src 生成 public/assets（剥底/切帧/atlas），
            源文件名全部中性（enemy_*）。
```

## 调试 / AI 测试 API

页面加载后暴露 `window.__CNM__`（JSON 指令协议，与 Godot 旧版 cmd-port 同构）：

```js
__CNM__.exec({ id: 1, action: "status" })   // status/game_state/start/input/choose/
__CNM__.getEvents()                          //   force_combat/spawn/give/teleport/
                                             //   goto_round/continue/quit 等（详见 sim/exec）
__CNM__.sim                                  // GameSim 实例（深度断言用）
```

`input` 指令与真实键盘叠加、持续有效；模态打开时 sim 自动清空游戏输入（模态独占输入硬约束）。

## 命令

```bash
node tools/gen-sketch.mjs   # 重新生成简笔画源图到 assets-src（调造型后需重跑）
npm run assets:sync         # 从 assets-src 生成 public/assets（剥底/切帧/atlas）
npm run dev                 # Vite dev server @ 127.0.0.1:5173
npm run build         # 自动先 assets:sync（prebuild）+ tsc 类型检查 + vite build
npm test              # vitest 逻辑回归
npm run e2e           # Playwright E2E（自动先 assets:sync 再起 dev server）
npm run preview       # 本地预览 dist 产物 @ 127.0.0.1:4173
```

## 构建 / 测试 / 部署

- 安装与测试：`npm ci` → `npm test`（vitest，sim 层逻辑回归）→ `npm run build`
  （prebuild 自动执行 `assets:sync` + tsc 全量类型检查 + vite 产物）。
  `public/assets/` 为生成产物不入库，`npm run build` 会自动同步；
  手动同步：`npm run assets:sync`。
- e2e：`npx playwright install`（首次需安装浏览器）→ `npm run e2e`
  （Playwright，自动先 assets:sync 再起 dev server，完整对局闭环）。
  断言对帧率计时敏感（串行 + 零重试），仅本地手跑，不进 CI；
  全量 e2e 对机器负载敏感，建议空载运行（此前实测批量跑偶发超时、单跑通过，属已知特性）。
- 部署：`dist/` 为纯静态产物，由 nginx 直接托管，无服务端。默认以**根路径**
  部署（如 `https://<域名>/`）；子路径部署时构建前设置 `VITE_BASE`
  （如 `VITE_BASE=/zhanyao/ npm run build`，值需带首尾斜杠），不设则保持根路径。
  可用 `scripts/deploy.sh` 一键完成「门禁 → 构建 → 版本戳 → 推送」：
  - `./scripts/deploy.sh` — 先跑 `npm test` 门禁，再 `npm run build`，并在
    `dist/` 写版本戳 `.deploy-version`（git describe 一行 + UTC 构建时间一行）；
  - `./scripts/deploy.sh --smoke` — 构建后起 `npm run preview` 并 curl 断言 200；
  - `SERVER=user@host REMOTE_DIR=/srv/cnm ./scripts/deploy.sh --push` —
    经 rsync 推送 `dist/` 到 nginx 托管目录；SERVER/REMOTE_DIR 必须显式给出，
    缺失时脚本直接报错退出（防误推）。

## 操作

- 移动 WASD/方向键，攻击 空格（按住连击，**全部装备武器同时齐射**），冲刺 Shift（HUD ⚡ 指示就绪）
- **开局职业**：欢迎页三选一（纯鼠标选卡，开局后锁定）——剑修（起手铁剑，伤害 +15%，
  开局即开放）/ 弓手（起手弓箭，攻速 +15%、冲刺冷却 -20%，累计击杀 50 解锁）/
  术士（起手法杖，范围 +20%、拾取半径 +50%，讨伐妖王解锁）；
  外观随职业起手武器自动对应近战/远程/法师
- **方向攻击**：近战朝移动方向挥砍（±55° 扇形判定），锥内妖物自动吸附瞄准，出手带
  突进位移——朝哪走朝哪砍；Tab 切目标已移除（吸附瞄准取代）
- **打击反馈**：妖物被打会硬直后退（速度制击退+指数摩擦）、蓄力被打断；命中音效
  随机变调、暴击高亢；死亡碎片沿受击方向飞溅

## 美术（简笔画速写本风格，v2 填充式马克笔）

全部角色贴图与地面由 `tools/gen-sketch.mjs` 程序化生成，迭代造型 = 改生成器参数
后重跑 `node tools/gen-sketch.mjs && npm run assets:sync`（seed 固定，产物可复现）。
风格规范（新增资产必须沿用）：
- 绘制系统：blob() 平滑闭合色块填充 + 炭描边为主，line() 粗笔作四肢/细节；
  Catmull-Rom 平滑 + 抖动 ≤0.45（简洁 = 自信干净的线条，抖动只在边缘呼吸）；
  主体色块加白弧高光（shine 工艺）；角色脚下淡落影；
- 调色：纸白 #f5eede / 炭棕描边 #332e29 / 铅笔灰 #8a8175 / 血红点缀 #c0392b
  （妖物眼/符箓/火）；填充为哑光纸感中调色（每色通道色散 ≥0.09，且需在 1:1
  游戏比例下可辨体积——过浅会被纸底吞掉）；
- 眼睛统一「墨点 + 白高光」；妖物有血红点睛元素，玩家无红眼——敌我一望可辨；
- 布局约定：玩家 walk/attack = 96×96 cell 紧排网格（8×1/6×1）、idle = 2×2 网格；
  妖物 = 128×96 cell 水平排列留 28px 间隔（投影分割拉伸切帧）；
  欢迎页插画 = genTitle() 独立场景（800×340，复用 drawPlayer/ENEMIES 画手）；
- 管线注意：玩家/妖物源图为透明 PNG，sync-assets 对这两类跳过剥底（strip:false，
  剥底会侵蚀浅色填充），且不做水平翻转（v2 有明确朝向，面朝右 = view facing 正向）。
- 地面构图：8 个簇心的草石 marks + 一条铅笔小径，禁止均匀散点与污渍斑
  （简洁 ≠ 简陋：元素少而有序）。

### AI 生图资产（Gemini 等，2026-09 起）

在程序化生成器之外，允许经 AI 生图补充资产（妖物攻击/妖王形态、玩家
dash/hurt/death、武器图标、场景物件、分幕地面）。硬性流程：
1. 白底出图 → `.workwork` 内后处理（边缘泛洪去底，保内部纸白填充；分帧归一），
   达到与 gen-sketch 相同的源图格式后才可入 `assets-src`（玩家/妖物透明 PNG
   跳过剥底的原则不变）；
2. 源图布局沿用上文约定：玩家扩展动作 dash 4×1 / hurt 2×1 / death 6×1（96×96
   紧排），妖物攻击与妖王形态同妖物 walk（128×96 cell + 28px 间隔，瘦长全身像，
   妖物源文件名保持中性 enemy_*）；
3. 图标/物件 256×256 透明 PNG 入 `assets-src/sprites/icons/{weapons,props}/`，
   文件名 = 武器 defId / 物件名；渲染层对缺失资产一律回退（矢量线稿或既有动画），
   资产可以分批到位；
4. 风格规范（调色/点睛/无红眼/面朝右）与程序化资产同等要求，入 assets-src 前
   逐张目检。
